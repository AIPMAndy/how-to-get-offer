# SOP 01｜投递漏斗出了问题，先诊断哪里堵住

**输入：** 同一个时间窗的岗位记录、简历版本、JD链接、面试反馈。**输出：** 下周只改一两个变量的求职实验。

## 先定统一口径

| 当前最高进度 | 解释 |
|---|---|
| 已投递 | 提交申请成功，尚未有有效沟通 |
| 已回复 | HR或招聘方回复了与岗位有关的信息，但尚未约面 |
| 已约面 | 已经确定至少一次面试安排 |
| 面试中 | 实际参加过面试，流程仍推进/待定 |
| Offer | 收到录用意向/条款；是否为正式书面Offer另外标注 |
| 已结束 | 明确拒绝、岗位关闭、主动退出；应另记结束时曾到达的最远阶段 |

只用当前状态会低估历史推进。本项目看板可手动更改状态并保存每条岗位曾达到的最高阶段，因此能粗略统计历史推进数量；但没有保存每次阶段变更的日期，**不能用来计算时间窗内的严格转化率或归因**。需更精确复盘时，请使用完整CSV记录事件。

## 诊断树

**A. 没有回复：** 岗位是否真实？JD门槛是否满足？简历第一屏是否展示岗位最看重的能力？联系方式能否联系？是否过度集中在一家/一个渠道？

**B. 回复但无面试：** 薪资预期、到岗时间、城市、可投入程度是否有明显不匹配？沟通是否只讲自夸而没有具体证据？

**C. 一面不过：** 针对真实JD，能否清楚解释自己做了什么、选择依据和结果？基础知识缺口是否存在？

**D. 多轮面试不过：** 是业务深度、负责人经验、跨部门协作、成本意识，还是外部因素？仅凭“没通过”无法得出唯一原因。

**E. Offer谈崩：** 现金结构、职级、公司预算、入职时间、地点是否尚未对齐？先形成书面问题表再沟通。

## 7天小实验

1. 固定1类岗位和1版简历，针对5~10个确实匹配的职位做申请。数量视岗位供给调整。
2. 同时增加1项可观察改动，例如第一屏项目证据或更有针对性的联系信息。
3. 记录每次申请的来源、日期、回复及具体拒绝理由。
4. 一周后看是否产生清楚的信息增量；小样本变化不能宣称某修改“让转化率翻倍”。

**完成标准：** 有具体排查结果和下一周动作，不以“猜到算法针对我”作为结论。
